> **适用边界（先读）**：只管「从 0 给一个人搭一个新台子」的**搭建期**。
> 它**不改动**主文件的数据驱动内核——第一性原理、23 条铁律、定时抓取 / stale / 发布回归 /
> 协作铁律 / 红线，一条没动。**3-4 模块闸门只约束首次搭建，不约束给已有台子加功能**

## 一、为什么补这一段

有些能力早就在骨架里实现了，却没上升成主文件的规则；AI 照主文件从 0 搭新台子时不会自动带上：

| 能力 | 骨架 / 参考里已有 | 主文件 SKILL.md |
|---|---|---|
| 函数 DAG + `refreshAll()` 统一入口 | `examples/minimal/index.html` L613-625，注释写明「DAG 单向调度」 | 全文无调用链约束 |
| 预置示例数据 + 当场落盘 | 同上 L255-273；`scripts/README.md` L92 记着「4 条变 1 条」的真 bug | 无正面规则，第七节红线反而写了「交付包里留着示例假数据」 |
| 触控 ≥44px / 底部安全区 | `references/visual-qa.md` L164、`index.html` L147 / L157 | 铁律 16 讲的是 CSS 坑，没有数值 |
| 3-4 模块闸门 / 先骨架后增量 | — | 阶段 1 第 2、3 条**已有**，不用补 |

（这张表逐条 grep 整个 skill 目录核对过，不是印象。）

所以这一段做的是**从代码反提为规则 + 补漏 + 裁决口径冲突**。

## 二、补进来的 8 条（编号 G1-G8，不占用主文件 23 条铁律的编号）

**G1 函数调用链必须是 DAG，只有一个统一刷新入口。**
数据层（读写 storage）→ 计算层（过滤 / 排序 / 聚合）→ 渲染层（更新 DOM）单向；
渲染函数之间严禁互调；所有交互一律「改数据 → 存 → `refreshAll()`」；
初始化在 `DOMContentLoaded` 里按固定顺序走完，不许各渲染函数自己触发别人。
落地位置：骨架 `index.html` L613-625；主文件此前无调用链约束。
适用：所有台子。这类循环语法正确、静态检查拦不住，一跑就是栈溢出白屏。

**G2 代码生成完，立刻过 8 条冒烟自检，再进主文件铁律 15 的发布前四道关。**
主文件铁律 15 管的是「发布前」，偏 jsdom 和视觉；缺的是「刚写完就默读一遍」这一层：
① 调用链无环 ② 初始化链路通畅、被调函数都已定义 ③ 所有 `getElementById` / `querySelector` 目标存在
④ 空数据不崩（含清空示例之后）⑤ 跨月 1/31→2/1、跨年 12/31→1/1 的日期边界
⑥ 事件绑定在 DOM 渲染完成之后 ⑦ 变量作用域、循环内闭包变量正确捕获 ⑧ 模块数与规模合规。
本条为补漏：其中 **⑤ 和 ⑦ 主文件与参考全文 grep 无**。

**G3 「今天要处理」置顶，逾期自动顺延。**
有任务 / 打卡 / 固定序列类数据时，首屏列出「逾期未完成 / 今天该做 / 快到期」，
逾期标红且每条给一键处理按钮，**昨天没做完的自动滚到今天，不许凭空消失**。
衔接主文件铁律 18「首屏那句话必须有变量」、阶段 4「决策驾驶舱」。
边界：**只对有待办类数据的台子**。纯情报流 / 指标监控型台子首屏仍是决策驾驶舱，别硬塞待办。

**G4 冷启动示例数据 —— 含一处必须裁决的规则冲突。**
「首次打开有 3-5 条示例（含 1 条逾期）」与主文件第七节红线「交付包里留着示例假数据」看似打架。
其实不矛盾：红线反的是**把假数据当成真账目交付**（用户以为数据串了），不是反「给示例」。
同时成立的五个条件，缺一不可：
1. 每条带 `demo:true`
2. 首屏有「清空示例数据」按钮，**只删 demo 项，不碰用户录入**
3. 内容不像真人账目（不写真实金额、姓名、以假乱真的日期）
4. **铺完当场落盘**：只在内存里铺种子，第一个写操作会把种子整批冲掉，4 条变 1 条且不报错
5. 数量 3-5 条，其中 1 条逾期
落地位置：骨架 L255-273、`scripts/README.md` L92 那个真 bug。
这是本节最值钱的一条：不裁决，AI 照主文件会自相矛盾，不知道该铺还是该清。

**G5 移动端补齐具体数值。**
按钮 ≥44×44px（儿童向 ≥50px）；输入框字号 ≥16px（否则 iOS 自动放大页面）；
数字输入用 `type="number"`；窄屏（<768px）单列；PC 侧栏 → 移动端底部 Tab / 汉堡菜单；
`padding-bottom: env(safe-area-inset-bottom)`；表格改卡片列表或卡内横滚。
44px 与安全区在 `visual-qa.md` L164、`index.html` L147/157 已有。
与主文件铁律 16 的 CSS 坑（`overflow-x:clip`、`minmax(0,1fr)`、`min-width:0`）**叠加执行**，不冲突。

**G6 数据备份是硬要求，不是出问题后的补救。**
localStorage 方案下，**首屏**放「导出 JSON 备份」「导入恢复」两个按钮（不许藏进设置）；
导入支持上千条、无条数上限；清空数据二次确认；记账类额外给「导出 CSV」；
数据攒到 30 条时顶部温和提示一次「建议导出备份」。
主文件第六节抱怨表只有「给导出 / 迁移入口」一句，此处成规则。
边界：有用户录入数据的台子才需要；纯只读情报台不必。

**G7 国内习惯。**
货币统一 ¥；日期 YYYY-MM-DD 或 MM月DD日；记账类支出红、收入绿。
注意：**金融 / 股票场景仍是涨红跌绿**，跟记账的红绿不是一回事，别混用。

**G8 迭代向后兼容。**
每次只加 1 个模块或改 1 处样式；**新模块用新 key，不改老键**；不丢已有 localStorage 数据。
与主文件协作铁律 1「不要顺手优化他没让你改的地方」是同一件事的两面。

## 三、按需加档（用户提出才做，不是默认动作）

| 触发 | 加什么 |
|---|---|
| 「想在手机上用」「想分享给别人」 | 必须交付**在线链接**——微信里打不开本地 HTML 文件；部署完自己先打开验一次；拿到链接教「浏览器打开 → 分享 → 添加到主屏幕」 |
| 宝妈育儿场景 | 孩子 / 家长双 Tab，家长模式 4 位密码；家长发任务、设奖励、确认兑换，孩子只能看 / 打卡 / 兑换；儿童向字体放大、按钮 ≥50px |
| 要传图 | 压缩到 800px 宽、最多 9 张、base64 内联，不引外链 |
| 部署上线 | **不能预填真实隐私数据**；密码只是防误触，不宣称加密；部署后链接公网可访问 |

隐私那条与主文件红线「把个人数据焊死在代码里再挂到公网」是同一件事，合并执行即可。

## 四、第三条路：在线数据表同步（架构选择，不替换原判断）

主文件第八节写「不承诺多设备自动同步（纯静态 + localStorage 原理上做不到）」。
这句话**在该架构内成立**，不等于技术上做不到。按主文件铁律 17 与协作铁律，把「补什么、代价是什么」列清楚：

| 路径 | 能同步吗 | 代价 | 什么时候选 |
|---|---|---|---|
| 纯静态 + localStorage | 不能 | 零依赖、离线可用；换设备数据不跟走，靠同步码迁移 | 默认，一个人一台设备 |
| 同步码（前缀 + base64） | 手动迁移 | 不是加密，必须明写「同步码等同于 Key，只发给你自己」 | 换设备时 |
| 在线数据表 | 能，在线双向 | 页面依赖平台运行时，**不再是纯离线单文件**；要写降级（断网暂存 localStorage、恢复后批量同步）+ 同步状态指示器 + 冲突以最新时间戳为准、合并保留双方新增 | 用户明确要「多设备 / 手机电脑都要用」 |

本表按架构列代价，由场景决定，**不改成「在线数据表优先」**：那会破坏零外链、离线可用的地基。

## 七、一轮搭建里怎么用

1. 主文件阶段 1 定位 → 规模闸门
2. 生成骨架时先按 G1 定 `refreshAll()`、按 G5 定数值、按 G4 铺种子并**当场落盘**
3. 代码写完**立刻**过 G2 八条，再进主文件铁律 15 的发布前四道关
4. 有用户录入就按 G6 放导出 / 导入；有任务类数据就按 G3 置顶
5. 用户提「手机上用 / 分享 / 给孩子用 / 传图」才走第三节加档
6. 迭代只按 G8 动一处
