# 视觉验证方法

跟 `visual-system.md` 配套。**凡是改了主题、皮肤、透明度、层级，都应该跑一遍**，
而不是等用户截图来问"怎么看不见了"。

这一节的大部分内容是**探针本身的坑**。写探针最危险的地方在于：
它有 bug 的时候会稳定输出"全部通过"或"全部不合格"，两种结果你都会信，
而真相可能正好相反。

## 一、为什么要自动化

肉眼判不了两件事：

1. **半透明层叠加之后的实际颜色**。三层各带 alpha，压出来的结果跟任何单层的色值都不一样，
   靠"我记得背景是白的"去判断必然错。
2. **全部组合**。N 套皮肤 × 深浅 × 全部视图，规模是几十个组合、上万个文本节点，人手扫不完。

> 真实代价：曾经凭"这是白底"的印象把一处 5.18 的改到 2.42，帮了倒忙；
> 另一次八种组合的扫描其实全被弹回同一套皮肤，报出来的"全部通过"是假的。

## 二、对比度探针的四个必错点

四个都犯过，缺一样结果就是假的。按重要性排：

### 1. 叠加顺序别写反

收集到一串背景层之后要从**最近的一层往外合成**：

```js
// 对：近层在上
stack = stack ? over(layer, stack) : layer;

// 错：远层压在近层上
stack = stack ? over(stack, layer) : layer;
```

以前全是实色底时看不出来（第一层 alpha=1 就提前返回了），一旦出现半透明层就全错。

### 2. alpha 合成要保留 alpha

```js
function over(fg,bg){
  var a=fg[3];
  return [ fg[0]*a+bg[0]*(1-a),
           fg[1]*a+bg[1]*(1-a),
           fg[2]*a+bg[2]*(1-a),
           bg[3]*(1-a)+a ];        // 别写死成 1
}
```

结果 alpha 写成 1 的后果：遇到"同色相叠两层"（比如 .16 再叠 .10）会提前收尾，
把一层淡底当实色算。

### 3. filter 的补偿方向：从 root 往下累乘

CSS filter 成组作用于**该元素及其子树**，不会把祖先的背景一起压暗。
所以补偿系数必须顺着 root → 祖先 → 当前元素累乘。

反过来写（把后代的 filter 也算进祖先背景），会得到一整屏假阳性。

### 4. 渐变背景要取全部色标的最坏值

`linear-gradient` / `radial-gradient` 元素的 `backgroundColor` 是**透明**的，
要解析 `backgroundImage`。

而 `backgroundImage` 里每一个色标都可能是文字背后的实际底色——
**取全部色标逐个当候选、取对比度最差的那个**。只取第一个色标，等于默认整屏文字都停在最亮那一处。

另外补一条：玻璃卡、模糊层这类半透明背景之上，
背景色就是从上往下取到的层合成结果，别跳过那一层。

## 三、headless 浏览器的三个坑

用 `chrome --headless=new --dump-dom` 注入探针时：

### 1. 页面启动会把存档的主题/皮肤写回 `<html>`

工作台普遍会在启动时从 localStorage 读回主题偏好再写回标签属性。

**所以在文件里改 `<html data-skin="...">` 的属性完全无效**——探针还没跑，值就被覆盖了。
必须在运行时切换：

```js
applySkin('serene');                                // 皮肤
document.documentElement.setAttribute('data-theme','light');  // 明暗
```

这一条不查，八种组合的扫描会全部落在同一套默认皮肤上，然后报"全部通过"。

### 2. requestAnimationFrame 不执行

headless 里 rAF 根本不回调（`–rAF=no`），凡是用 rAF 驱动的动效（倾斜、浮动、光泽）一律测不出来。

```js
window.requestAnimationFrame=function(f){return setTimeout(f,16)};
```

先 polyfill 再断言，不要把"代码没生效"当成"代码有 bug"。

### 3. 探针输出要用锚点元素取，别只搜哨兵字符串

探针 JS 源码里也写着那两个哨兵字面量，正则直接搜字符串会咬到源码里那份。
把结果写进一个专门的元素再用它当锚点：

```html
<pre id="__O"></pre>
```

```js
var ms = re.findall(pattern, dom); var raw = ms[-1];  // 取最后一次出现
```

## 四、验收门槛

跑完要满足，不满足别发布：

- **对比度**：全部皮肤 × 深浅 × 全部视图，低于 3:1 的条目数必须为 **0**
- **溢出**：至少 **320 / 375 / 414 / 768 / 1280** 五档，每个视图 `scrollWidth ≤ 视口宽`
  （320 是 iPhone SE 那档老机型，最容易漏；只在 390 上验过的话，SE 上必炸）
- **CSS 语法**：解析一遍，0 错误

一个必须有的心理准备：**探针修好之后，往往会暴露出一批"早就存在、一直没被发现"的低对比度**。
那不是这次改坏的，是历史欠账，一并修掉并在交付说明里写出来，别假装没看见。

## 五、这条路走不通，别再花时间

**像素级校验在本机架不起来**，三个死结：

- 环境里没有 PIL/Pillow，装不上
- 换浏览器自己解码图片，`file://` 的图必须带 `--allow-file-access-from-files`
- 大图走 data URI，在 `virtual-time-budget` 里解码不完，`--dump-dom` 出来时是空的

结论：**不要用像素比对做视觉验证**，用对比度探针 + 截图看。时间花在这里是纯亏损。

## 六、故障清单：这些报错对应什么

| 现象 | 实际原因 |
|---|---|
| 八种组合扫描结果完全一致 | 触发了上面的坑 1，全落在同一套皮肤 |
| 动效断言全不过，但肉眼看页面是对的 | 坑 2，rAF 没跑 |
| 探针输出一直是源码里的那份字符串 | 坑 3 |
| 同一个元素反复报不合格，改了还是它 | 多半是背景层没取对（渐变 / 兄弟节点上的背景没被找到） |
| 报了一屏不合格，看起来不可能全错 | filter 补偿方向反了，见必错点 3 |
| 浅色模式大面积不合格 | 大概率是"只换了强调色没换整套底和字"，见 `visual-system.md` 第四节 |


## 七、移动端六条硬规则（溢出检查之外的部分）

> 溢出（`scrollWidth`）只能验出「横向滚动条」。下面六条是溢出之外、但又必然会在手机上出事的：
> 尤其是 M1——**它在视觉上完全正常，只是所有吸顶功能悄悄失效**，肉眼查不出来。

| 编号 | 规则 | 为什么 / 怎么验 |
|---|---|---|
| **M1** | `html` 和 `body` 两处都写 `overflow-x: clip`，**不许写 `hidden`** | `hidden` 会把根元素变成一个滚动容器，**所有 `position:sticky` 后代静默失效**（顶栏、侧栏跟着滚走了）。页面看起来正常，所以没人会报这个 bug |
| **M2** | 含图片的网格轨道写 `minmax(0,1fr)`，不写裸 `1fr`；flex 子项加 `min-width:0` | 裸 `1fr` 的最小尺寸是 `auto` = 图片原始宽度，它不会被压缩，于是把轨道撑爆（这条我们已有，见 SKILL.md 反模式表） |
| **M3** | 可点击的文字在**任何宽度**都不许换行 | 换行后第二行常常落在热区外，或者两个链接挤成一坨。先缩短文案，再考虑 `nowrap` |
| **M4** | 大标题带 `overflow-wrap:anywhere; min-width:0` | 一个长英文单词或一长串品牌名就够把它撑出屏幕 |
| **M5** | **整屏只允许一个 `sticky; top:0`**，其余要吸顶的元素必须按 `--nav-h` 偏移，z-index 也要分层 | 两个都写 `top:0` 会互相盖；写成 `--nav-h` 偏移才有先后 |
| **M6** | 全大写标题 `line-height` 下限 `1.0`（推荐 1.02–1.08） | 见 `visual-system.md` 第八节：没有降部，行高一压两行就糊成一条墨带，窄屏必撞 |

两条配套：

- **`min-h-dvh` 而不是 `100vh`**：手机浏览器的地址栏会让 `100vh` 比实际可视区高，底部会甩出屏幕。
- **触控目标 ≥ 44px**，并且要有 `:active` 反馈。手指按不到、按了没反应，用户只会觉得这个东西坏了。


## 八、动效的无障碍底线

- **`prefers-reduced-motion` 必须有「终止态」，不是把动画关掉就完事。**
  动画要被冻结在一个**看起来已经完成的静止画面**上：进度条停在 100%、数字是最终值、
  卡片在最终位置、已经展开的区块保持展开。**只把时长压到 0 而状态没落地，
  等于发布了一个永远停在中间态的坏版本**——用户看到的不是静态页，是一个卡住的动画。
- 做法：`matchMedia` 在顶部探一次拿到开关，每个动效分别走「有动画 / 直接设终止态」两个分支；
  CSS 里再配一条兜底：

```css
@media (prefers-reduced-motion: reduce){
  *{animation-duration:.01ms!important;transition-duration:.01ms!important}
}
```

- **跟指针有关的动效**（跟随鼠标的倾斜、光泽、磁吸按钮）要再套一层 `(hover:hover) and (pointer:fine)`，
  否则触屏上会出现「点一下卡片先歪一下」的鬼畜。
- 动画只动 `transform` 和 `opacity`，不动 `top/left/width/height`——后者每帧都要重排，中低端机直接掉帧。
