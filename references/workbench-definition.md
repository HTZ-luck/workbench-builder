# 工作台定义层

**这份文档解决一种特定的失败：页面生成那天是满分，第三十天没人打开。**

工程那套（抓不到不编、失败不冲数据、每个数能点回去核）保证它**说真话**；
这份保证它**有话可说**。两条缺一条，台子都是死的——只是死法不同：前者骗人，后者没人看。

> 这一节是我们踩过坑之后补的。
> 我们自己的工作台此前只做到"数据必须是真的"，**没有约束首屏那句话本身有没有东西产生它**。
> 下面每条都指向一个具体的失败，不是审美偏好。

---

## 一、打开时刻：必须点名一个时刻

**一个工作台是在某个时刻被打开的，不是"有空的时候"。** 名字要说出来：早上睁眼第一件事 · 通勤路上 · 拍完素材刚坐下 · 睡前躺床上 · 周一排本周选题时 · 发完作品等数据的那两天 · 月底回头看这个月的时候。

| 这条决定了 | 怎么决定 |
|---|---|
| 钩子的时态 | 早晨的钩子是命令句（今天该做什么）；晚上的是回看（今天怎么样） |
| 当天他能承受多少输入 | 没人会在 23:50 填一张表单，但同一个人在早上通勤能点三下 |
| **要不要回来的理由** | 一个网页没有推送、没有角标，打开的那一刻不在他的一天里，它就造不出一个新时刻 |

> **这条对纯网页比对 App 更致命。** App 能用一条通知把弱的时刻买回来；浏览器标签页不能。
> 所以要么挂在他已经在做的事上，要么诚实把节奏降到"每周看一次"，并按周更来设计。

**验法**：说不出时刻 = 没有节奏 = 会被好奇心打开两次。这时候不要硬造一个"每天早上看一眼"，
改成问他现在什么时间会想起这件事，或者明确按周更做。

## 二、四种写入者（决定它是数据还是传说）

> 这四种写入者的分类框架是行业通用的方法论，但举例、成本和陷阱全部按我们自己的场景重写
> （这里以自媒体创作台为例）。**分类可以共用，判据不能照抄。**

第〇节那三个问题里，"这个字段是谁写进去的"是最难回答、也最定生死的一问。四种答案：

| 写入者 | 谁写 | 成本 | 陷阱 |
|---|---|---|---|
| `user` | 他亲手填 | **最贵的资源** | 每个模块派三个字段给手填，等于悄悄给他安排了一份全职录入工作。**要数一数一共几个** |
| `system` | 台子自己在"某件本来就会发生的事"的副产物里写下来（跑完一轮 → 一条运行记录；拖动阶段 → 最后活动时间） | 免费 | **这是最优解，优先找它**。多数好钩子读的都是 system 写的字段 |
| `integration` | 别的系统给（接口回传 · 设备上报 · 导入表格 · 平台 API） | **只有那个对接真的存在时，这个字段才存在** | 最常见的谎：「数据从某某平台来」，然而没有账号、没有接口、没有日期 |
| `derived` | 读的时候从别的字段算出来（超期 = 现在 − 最后活动 > 7 天；缺口 = 目标 − 已完成） | 免费 | 只跟它的输入一样真。**输入是个没接成的 integration，它就不是免费，它是虚构的** |

**规则**：

1. 首屏那句话里的每个字段必须能点名写入者；**`integration` 写的字段必须点名源系统、并写明它今天是否已经存在**。
2. **依赖没接成，就把那个数从首屏拿掉**，别留着等以后补——这是「抓不到就是抓不到，绝不编」（铁律 4）在字段级的版本。
3. 数一遍派给 `user` 的字段。**超过 3 个日常手填字段的台子，大概率活不过两周。**

## 三、首屏那句话的三条硬约束

### 3.1 必须有变量

**没有变量的句子是被明确禁止的**，不是"不够好"。

```
今天也要加油哦              ← 什么都不需要，所以它什么都没说。禁止
今天是第 3 天 · 今日 3 件事  ← 需要：一个起始日期（他填一次）
4 个在跑 · 1 个昨晚失败      ← 需要：运行状态（system，每次跑完落一条）
12 个待跟进 · 3 个超 7 天没动 ← 需要：阶段 + 最后活动时间（拖动时自动落）
```

**理由**：它在提案里读起来很漂亮，没人会当场否决「今天也要加油哦」；所有人都会在周四忽略它。
**这是这一类页面最常见的失败，而且在定义的时候完全看不出来。**

### 3.2 被总数冒充的钩子

「共 1,284 个客户 · 本月新增 32」技术上会变，但没告诉他今天要做什么。
**首屏那条必须至少有一个指向"今天要动手"的子句** —— 待跟进 · 超期 · 失败 · 告警 · 缺货 · 待审批。
否则它是一条数据带，不是钩子。

### 3.3 第 40 天测试

把首屏按**第 40 天、这一天什么都没记、定时任务也没跑**渲染一遍：

| 渲染结果 | 判定 |
|---|---|
| 跟第 1 天读起来一样 | 它不是钩子，是一句恰好放在页面顶部的装饰 |
| 空着、`--`、一张零行表 | **他没有第二天**（见第六节 D6） |
| 谎称一切正常 | 断更在静默骗人 → 落到 stale 三件套（铁律 6） |

> 我们自己的答案比同类生成器更硬：不是画一遍样子，而是**管道真跑、stale 真渲染**。
> 但"第 40 天"这个动作仍然要在设计阶段先过一遍——等到页面都搭完了才发现这个位置没有数据源，只能回来改口。

## 四、他不肯给的输入：按这四步降级，顺序不能乱

发现某个字段只能靠他每天手填时，**不要把它写进需求里，先往下走**：

1. **推出来**（星期几 → 今天练哪块；一个考试日期 → 还剩几天；支付回调 → 订单状态；`最后活动时间` + 现在 → 超期）
2. **只问一次，不是每天问**（周期开始日、宠物生日、月度目标、告警阈值）
3. **把日常输入压成一个点击**，带一个 sensible 默认值（「和昨天一样」、卡片拖一列）
4. **换一句够得着的钩子**

> 第 4 步是成功不是妥协。**一句真的小话，胜过一句假的大话。**
> 很多人在第 1 步就放弃了，直接要求用户手填，然后在第四周长出一份他再也不肯填的表单。

## 五、十一种结构（比"给谁用"有用得多）

**按数据怎么运转分类，不要按人群分类。** 人群是无限的（经期 / 增肌 / 考公 / 记账 / CRM / 医疗 / 工厂），
列出来是一张宣传单，对下一个台子没有任何指导。**结构只有十一种**，而结构决定：钩子句式 · 首屏形状 · 数据模型骨架 · 回访机制 · **它特有的死法**。

行业完全不同但结构相同的两个台子，工程上是一回事——这才是分类的意义。

### 个人域主导

| 结构 | 引擎 | 钩子句式 | 特有死法 |
|---|---|---|---|
| **cycle** 周期 | 一个可计算的外部节奏（周期、孕周、距考试、疫苗） | 「你在第 N 天/阶段 → 因此今天…」 | 锚点日期从没被填进来，于是 N 根本不存在 |
| **ledger** 累积 | 每天一条记录，价值在累积出的曲线（体重、记账、背词、打卡） | 「今天 X / 目标 Y，还差 Z」 | **录入债**：断三天曲线就显得毁了，于是他停了 |
| **state** 状态 | 今天的状态，不需要累积（睡眠复盘、情绪、持仓体检） | 「昨晚/今天你是 X，所以 Y」 | 每天都同一个 X，于是它不再是信息 |
| **runbook** 序列 | 今天规定要走的一段流程（训练计划、仪式、刷题） | 「今天这 N 件事」 | 每天都一模一样 list —— 那用个闹钟就够了 |
| **care** 照护 | 另一个对象的状态（宠物、婴儿、植物、老人） | 「它/他第 N 天 · 今天该…」 | 只有里程碑，没有每天打开的理由 |
| **feed** 情报 | 外部信息被挑选并翻译成人话（情报流、早报、工具速递） | 「今天这 3 条 + 一句人话」 | 内容跟别处一样泛，没有他个人的筛选口径 |

### 钱货在动

> 结构分类名（`operation`/`pipeline`/`registry`/`console`/`monitor`…）是行业通用术语，可以共用；
> **每种结构的钩子句式、特有死法都是我们按中文口语原创重写的**——
> 句式是表达，不能照搬别人的句式。

| 结构 | 引擎 | 钩子句式 | 特有死法 |
|---|---|---|---|
| **operation** 经营 | 钱和库存在流动（摆摊、小店、进销存、电商后台） | 「今天进了 X · 有 Y 样该补货了 · 先去处理 Z」 | 记账比笔记本还累；库存那个数从来没真过 |

### 系统域主导（个人也可能用到）

| 结构 | 引擎 | 钩子句式 | 特有死法 |
|---|---|---|---|
| **pipeline** 推进 | 对象沿有序阶段往前走（商机、订单、工单、项目任务、待审内容） | 「还在走的 N 个 · 卡了 K 天没动的 M 个 · 今天就推那两个」 | 没人拖卡片，所有对象永远停在第一阶段，看板是假的 |
| **registry** 目录 | 可检索的对象册子，有列表页和详情页（资料库、商品库、学员、病历、书单） | 「新收进来 N 条 · 有 M 条还缺东西没填 · 刚动过的在这」 | 第一天是空的，又没有每天打开的理由，最后变成只有搜索时才来的地方 |
| **console** 控制台 | 一堆在跑的东西，能启停能干预（Agent、定时任务、设备、服务） | 「跑着 N 个 · 挂了 M 个 · 花了 X」 | 从来不会失败得有意思，于是整屏绿墙没人读 |
| **monitor** 监控 | 指标聚合 + 异常，能下钻（看板、持仓、运营监控） | 「今天走到 X，要的是 Y · 有 N 处不对劲 · 最该看的是这个」 | 只有数字没有异常 = 墙纸；不能下钻 = 抛出一个它答不了的问题 |

### 怎么用这张表

- **多数真台子是"主结构 + 副结构"**：养宠 = care + ledger；创作台 = feed + monitor + ledger；CRM = pipeline + registry。**主结构决定首屏和钩子**，副结构贡献一两个模块。一个台子说自己有三种结构，通常是三个台子——把话说出来让他挑。
- 边界情况按"数对象和数层级"判，**不按人数判**：「个人资料库」听着是个人域，其实是 `registry`（有 N 篇、有列表页详情页）；「摆摊工作台」听着像生意，其实是个人域（一个人、一个时刻、没有页面深度）。
- **诚实标注**：我们只深度搭过 `feed` + `monitor` + `ledger` 三种（那个自媒体创作台）。用到没搭过的那几种时，第一版按最小可行搭，用真实使用补经验，**不要照着这张表硬填模块**。

## 六、遗弃黑名单：交付前逐条过

> 这是「怎么在第三十天失去他」的清单。**任何一条不通过都是定义级缺陷**——
> 在这里修只要改一句话，等页面搭完再修要推翻整个首屏。

### D 列 · 个人台子（左边这列每行都要能答）

| # | 症状 | 怎么验 | 怎么修 |
|---|---|---|---|
| D1 | **首屏没有变量**（或变量没人产生） | 渲染第 40 天；跟第 1 天一样 → 不通过 | 第三节四步降级 |
| D2 | **货架式导航栏**：超过三分之一是"知识类"（科普、指南、动作库） | 数一下占比 | 合并成一个"说明"频道，腾出来的位置给记录和回看 |
| D3 | **录入债**：每天手填超过 ~60 秒，或三个频道各自要求每天记 | 把所有频道每天要花的秒数加起来 | 推导 / 默认 / 一键 / **砍频道**（砍是大家最不敢做、但常常是对的） |
| D4 | **没有回看频道**：他每天喂，没人回给他一句"你已经坚持 14 天" | `ledger` 或 `care` 台子上没有一个回看类频道 → 不通过 | 加一个：曲线 · 周报 · 相册 · 年报。攒了不发还是苦役 |
| D5 | **假的"今日"**：一个叫"今日 XX"的频道，内容每天一模一样 | 连看三天 | 换成有变量的钩子，或者干脆改成一个静态入口 |
| D6 | **空白冷启动**：第一天全是 `--`，于是他走不到第二天 | 空数据渲染一遍 | 第一天没数据时，屏幕必须说一句有用的话（下一步做什么，不是报错） |
| D7 | **频道太多**：一条记不住的轨道 | 数 > 9 → 不通过 | 合并到 4–9 条；多于这个数就变成一个他不再读的菜单 |
| D8 | **跟频道无关的变现位**：任何模块旁边硬贴商城入口 | 看它长在哪个模块上 | 要么长在已有模块上，要么没有 |
| D9 | **时刻不存在于他的真实一天里** | 说出他打开它的那一刻 | 挂到他已经在做的事上，或者诚实降为周更 |
| D10 | **它变成了一个管理系统**：一个人用的台子上加了角色和权限 | 看有没有第二个写数据的人 | 两个"读者"不是这回事；三个"角色"通常是多余的 |
| D11 | **它变成了一张监督表**：`care` 台子的对象会反对、钩子只报缺口、记录是"关于他"而不是"给他看" | 问一句：他本人看这张表会舒服吗 | 把反馈改成给他的，不是给别人汇报的 |

### S 列 · 系统台子（哪怕只用到一两个模块也要过）

| # | 症状 | 怎么验 | 怎么修 |
|---|---|---|---|
| S1 | **假数据演示**：规格里写着「12 个待跟进」，但没有任何字段能产出 12 | **用一个空数据库渲染首屏** | 这是 D1 的系统域版本，也是最贵的失败 |
| S2 | **列表页地狱**：每个模块的 L1 都是同一张"表格 + 搜索框 + 分页" | 九个模块九个一样的屏 | 主模块的 L1 必须是看板 / 曲线 / 待处理清单，不是表格 |
| S3 | **空的后台**：没有种子数据、没有导入路径、没有"第一个对象"的流程 | 第一天他能不能动手 | `cold_start.day_1` 必须是一个具体动作（导入一份名单 / 建第一个 Agent / 录一个客户），不是一句"暂无数据"的描述 |
| S4 | **名词模块**：「客户管理」「订单管理」「系统管理」 | 每个模块的"做什么"里有没有动词 | 名词 + 管理 不是一个能力，它是一次没做决定 |
| S5 | **虚构的对接**：钩子依赖某个还没接的系统 | 点名源系统 + 今天存在与否 | 不存在的就从钩子拿出来，或者明写成依赖 |
| S6 | **孤儿模块**：跟主对象没关系（客户台子里的"公司公告"） | 问它跟主对象的关系 | 砍掉或拆出去 |
| S7 | **为了对称造出来的三级页面**：L3 什么都没有 | 看有没有真子记录 | 没有就停在 L2，那是对的 |
| S8 | **角色编成了一张组织架构图** | 定义时超过 4 个角色 → 不通过 | 说出每天打开它的那一个人，先为他做 |
| S9 | **全是主模块**：九个模块一样重 | 有没有 `primary` | 权重相等是"从没决定过什么重要"的视觉形态 |
| S10 | **不能下钻的监控**：一个数字抛出了问题，但点不进去 | 点每个异常数字 | 或者能下钻，或者别放那个数 |

> **为什么这些能通过评审**：每一条单独看都很合理。「科普频道」免费命名、不向任何人要东西、还能把导航栏撑得看起来很充实；
> 「先留着角色权限」没人会当场反对；「以后会从 ERP 来」听着只是个排期问题。
> **它们全部是在"将来有人用"的尺度上是缺陷，在"现在看着挺好"的尺度上是优点。** 所以要逐条过，不要凭感觉扫一眼。

## 七、交付后就停下

定义交出去的那轮，**停**。不要再补第 9 个频道、不要再加一层页面树。
他回报的第一个修改才是真的需求——第一版的价值就是让他有能力说"不对，我不是要这个"。

> 一句话收口：**一个能挑错的工作台，胜过一场他必须坐完的访谈。**
