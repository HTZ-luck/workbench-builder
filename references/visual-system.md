# 视觉体系

第 4 阶段（渲染与呈现）用。讲工作台"长什么样"。

先说清楚本 skill 的定位差异：有些生成器把力气花在挑风格和出预览上，但它们生成的是静态空壳，数据全靠手填。
**我们这份的长处在数据管道**（脚本定时抓、断更告警、stale 三件套），所以视觉这一块不是"挑个色板"就完事，
而是要解决一件更难的事：**同一份结构要在任意皮肤、任意深浅模式下都看得清、都站得住**。
下面每一条都是实测翻车翻出来的，不是审美建议。

## 一、双轴属性：深浅与皮肤是两件事

用一个元素承载两个状态，别把"深色模式"做成"第八个皮肤"：

```html
<html data-theme="dark|light" data-skin="orange|blue|passion|serene">
```

- `data-theme` 管明暗：**换的是整层的底和字**
- `data-skin` 管调性：**在同一套明暗下换主色和底色倾向**

为什么必须拆开：合成一个 `data-style="dark-blue"` 之后，每加一套皮肤就要写两遍颜色，
加第三套时要么漏、要么两份开始漂移。双轴是相乘变加法——N 套皮肤只写 N 份强调色 + 1 份明暗规则。

### 皮肤清单必须数组驱动

切换器由一个 JS 数组长出来，不要手写按钮：

```js
var SKIN_LIST=[{id:'orange',n:'橙',c:'#ff5c33'},{id:'blue',n:'蓝',c:'#3b82f6'}, ...];
```

**恢复存档时的白名单校验必须走 `SKIN_LIST.some()`**：

```js
if(!SKIN_LIST.some(function(s){return s.id===sk})) sk='orange';
```

> 真实 bug：曾经写成 `if(sk!=='orange' && sk!=='blue') sk='orange';`。
> 加第四套皮肤当天，用户一切过去刷新就被弹回橙色，而代码看起来完全没问题。
> **白名单写死的一刻，就等于宣判这套皮肤不可用。**

新增一套皮肤要改的地方永远是这五处，少一处就是 bug：
1. root 上的明暗两版变量
2. 面板层的明暗两版变量
3. 弹层的明暗两版变量（弹层常落在面板作用域外，得自带一份完整调色板）
4. **root 上这一套皮肤自己的 `--dxac / --dxac2 / --dxacRGB` 兜底一行**
   （面板作用域之外拼出来的元素读的是 root 这份；漏了它，新皮肤在主作用域的强调色还是默认皮肤那个色，
   页面看起来"换了一半"——这正是上面那条"被弹回橙色"的同类 bug）
5. `SKIN_LIST` 里加一项

## 二、层次：三层底，缺一层就平

只有"页面 → 卡片"两层的工作台怎么看都像一张表格。要有三层：

```
页面底 (--bg)
  └ 面板 (--dxbg)        大面积容器、整个视图区
      └ 卡片 (--dxcard)  单条内容
```

三层的明度差建议控制在 **7%–20%**：小于 7% 三层糊成一层，大于 20% 就开始吵。

### 变量重映射（让外壳住进面板）

如果工作台有一套自己的外壳样式变量（`--card` / `--line` / `--ink` …），不要复制面板的样式去覆盖它，
**在面板作用域里把语义变量指过去**：

```css
.dx{ --card:var(--dxcard); --line:var(--dxb); --ink:var(--dxt); --ink2:var(--dxt2); --ink3:var(--dxt3); }
```

好处是外壳视图自动获得全部层次，且改面板只需改一处。配套两条：

- `.dx .dx{background:none;padding:0}`：防嵌套套壳，否则内部再套一层面板会翻倍出 padding
- `font-size` 重新锚定一次：面板为了信息密度会把字号压小，外壳进去后字会跟着变小

## 三、形状 token：圆角不许写数值

```css
--r-card:14px;  /* 卡片 */
--r-ctl:10px;   /* 按钮、输入框 */
--r-tag:6px;    /* 标签、徽章 */
--r-in:9px;     /* 内嵌块 */
```

**外壳和面板必须引用同一批 token。** 两套系统各自的圆角都"差不多对"时，看着就像两套东西拼起来的——
这是最伤整体感的一处，而且用户只会说"感觉不协调"，说不出是哪。

字号同理：抽成 `--fs-*` 阶梯并拉开跨度，全部地方引用。字号差相近（16/15/14）是业余感最大的来源。

## 四、深浅切换：最容易整屏翻车的一节

### 硬约束：底和字必须一起换，只换强调色等于整屏消失

常见错误是这样写浅色模式：

```css
:root[data-theme="light"]{ --accent:#1d4ed8; }   /* 只换了主色 */
```

结果：强调色是新皮肤的新颜色，但面板底色和文字还锁在深色那套——**浅底浅字，整屏看不见**。
浅色模式必须是整层替换：

```css
:root[data-theme="light"] .dx{
  --dxbg:#f1f4f9; --dxcard:#ffffff;
  --dxt:#0f172a; --dxt2:#475569; --dxt3:#64748b;
}
```

把"转浅"写在**通用层**（不带 `[data-skin=...]`），皮肤只在下面覆盖自己的强调色和冷暖倾向。
> 真实 bug：第一版把浅底规则挂在某一个皮肤名下，其余皮肤进浅色模式时主面板仍是深色的。
> 用户截图来问"为什么组件颜色还是深色的没有同步变化"——就是这一条。

### 强调色要比深色那档再压深

深色面板上用的主色，搬到白底往往只有 3.2–3.9。三档：

```css
--accent:#ff5c33;   /* 深色用 */
--accent:#c2410c;   /* 浅色用 */
--accentD:#9a3412;  /* 浅色下"实色块 + 白字"的元件专用 */
```

`--accentD` 存在的理由：凡是主色做实色底、上面压白字的小元件（精华标签、封面块、数字角标），
用上面两档都压不住白字。给这批单独一档，别让它们跟文字用同一个值。

### 行内写死的亮色：用 color 重映射，绝不用 filter

页面里总有一批颜色是直接写死的（JS 拼的样式、`style="color:#f59e0b"`），当初是配深色底的，
搬到浅底只有 1.9–2.7。两种写法，两种后果：

```css
/* 对：只改这个元素的字色 */
:root[data-theme="light"] .rv-dxi>i{ color:#475569; }

/* 错：filter 作用于整棵子树，会把整张卡连背景一起压暗 */
:root[data-theme="light"] .dx [style*="color:#"]{ filter:brightness(.55); }
```

用 filter 兜那次的结果是整张卡片被压成中灰，比不修更糟。

配套三条：
- **实色底 + 白字的元素要从 filter 列表里排除**（用了实色底又被压，白字反而更看不清）
- 已经有实色底的元素要改透视感时，先 `background:transparent` 再压，否则底和字一起暗等于白做
- `[style*=...]` 只能命中行内写死的那一批；CSS 规则里写死的得把选择器逐个列出来，**两边都要补齐**

### 别让需要互相区分的颜色跟着主色走

图表系列色、数据来源标签色、评分档位色、warn/danger——这批色的作用是"彼此能区分"。
跟着主色切换会糊成一片。换主题时不要动它们。

## 五、磨砂玻璃与环境光（质感层，可选）

规范里常被漏掉的一节：Elevation 不是靠投影，是靠**半透明板材 + 背景模糊 + 1px 亮边**。

三段式做法：

1. **铺场**：挂在 `body` 上铺一层有多色 radia 的暖/冷色池，`background-attachment:fixed`。
   > 必须挂 `body`。挂在某个装饰用的兄弟节点上，对比度探针顺着父链取背景永远取不到它，
   > 等于蒙眼调参——下面所有透明度都是在"我以为的背景"上算出来的。
2. **板材**：侧栏 / 大面板 / 卡片改成 rgba 半透明填充（浅色 .42–.50，深色 .58–.70，
   具体值按对比度余量定，不是拍脑袋）
3. **玻璃**：`backdrop-filter:blur(16px) saturate(1.3)` + 顶沿 1px 高光 + 一条极淡的同向渐变面

**最关键、也最容易漏的一条：板材必须比它后面那层亮。**

> 第一版把背景场也做成同色系的奶油色，结果半透明卡片铺上去跟背景几乎同色——
> 它是真的半透明了，但肉眼完全看不出来，等于没做。
> 把背景场压到明显有彩度的一档才出层次。这条不靠眼睛猜，用 `getComputedStyle` 量两条 CSS 变量的明度差。

环境不只是为了好看：**毛玻璃压在平涂色上，效果就是平涂色**。想"透"就必须底下有东西可透。

## 六、动效

三条够用，别再往上堆：

| 效果 | 做法 | 注意 |
|---|---|---|
| 浮动 float | `translateY(-4px)`，周期 4.2–6.4s，**逐卡随机延迟** | 全卡同相位会像整页在抖，必须散开 |
| 倾斜 tilt | `perspective(1400px)` + `rotateX/rotateY`，**角度要小**（±3 / ±4 度） | 第一版给到 ±6/±8，用户直接说"翻转幅度过大"。CSS filter 和 transform 都作用在整棵子树 |
| 光泽 glare | 跟着指针位置走的径向渐变白（约 13%） | 用 CSS 变量传 `--mx/--my`，别每帧写 style |

两条纪律：

- **必须尊重 `prefers-reduced-motion`**
- 这是每天开十次的工具，**动效要能被忽略，不能被注意**。宁小勿大、宁慢勿快；
  拿不准就砍掉，页面不会因为少了它而变得难用，但会因为多了一个烦人的东西而被关掉。

## 七、抄一个参考设计时的正确顺序

用户拿别人的页面让你复刻时：

1. **先找源站的实际 CSS/JS 文件**（通常是 `assets/app.css` 这种），不要只看截图对着猜。
   动效尤其如此——截图里看到的"会发光会飘"，在源码里往往就是几十行，
   而凭肉眼重新发明会做出完全不同的东西。
2. **搜索要搜全盘**，别只在当前项目里找。说"没有源文件"之前，先确认你是不是只搜了一个目录。
3. 复刻配色和布局，然后复刻层次，最后才复刻动效。顺序反了会在还没站住的时候就先做噪点。




## 八、质感底线：便宜的四条，贵的三条

> 这一节是对比同类生成器之后补的。之前这份文档只解决了「层次够不够」，没解决
> 「为什么一眼还是像 AI 生成的默认模板」。差别基本就在下面这几条——尤其前四条，几乎不花时间。

### 便宜但必须做（工具型页面也适用）

- **不许出现纯 `#fff` 和纯 `#000`。** 每个中性色都朝主色调偏几个点。
  纯白底配纯黑字是浏览器默认渲染的样子，用户打开的一瞬间就知道没人设计过它。
  底色和字色各自带一点色温，整屏观感立刻从「一份默认文档」变成「某个东西」。
- **描边一律用半透明 rgba**：深底 `rgba(255,255,255,.07–.22)`、浅底 `rgba(0,0,0,.06–.08)`。
  硬写一条 `#333` 的，放大看是卡了一条尺子在边上。
- **色锁（color lock）**：强调色选定之后锁死整个页面，不许再冒出第二个主角色。
  一颗跟主色不相干的绿按钮混进橙主色的页面，整屏立刻散掉。
  **例外**：图表系列色、数据源标签色、评级档位色、告警色——它们的工作就是互相区分，
  参见第四节末尾「别让需要互相区分的颜色跟着主色走」。
- **标题要有字重张力（type tension）**：`clamp()` 字号 + **负字距** `-.02em ~ -.045em` +
  `line-height .86–.95`，跟轻量正文形成强弱对比。
  **全大写标题是例外，而且不是罕见的例外**：全大写没有降部（g / y / p 伸到基线以下的笔画），
  行高 .86 时第二行的大写顶部会贴到第一行的基线和逗号，两行糊成一条墨带。
  **宽屏上它只占一行你看不出来，窄屏一换行必撞。**
  所以：`text-transform:uppercase` 的标题，**行高下限 1.0，推荐 1.02–1.08**。
  要么提行高，要么去掉全大写，别在 .98 上和稀泥。

### 贵的（看情况，我们这种每天打开的工具通常不需要）

- **噪点层（grain）**：一张固定的 SVG `feTurbulence` 噪点，`opacity .025–.05`（浅色再降一半）。
  它是静态的、不加任何交互成本，但压住了那种扁塌塌的「矢量色块」观感。
- **暗角（vignette）**：深色首屏上一道径向渐变压暗，给眼睛一个焦点。落地页用，工作台基本不用。
- **超大字重特写**：只在「这句话是唯一主角」的英雄位用。每天开十次的工具不需要。

**怎么选：噪点 / 暗角 / 超大字属于品牌页不属于工具页。**
上面「便宜但必须做」那四条才是通用底线。拿不准就只做那四条。

### 调色时用 OKLCH 思考

即便最后输出的是 hex，**思考的时候用 OKLCH**（感知均匀、明暗天然成对），
并且在设计的开始就把深浅两版一起定下来——**永远不要做完深色再整体反转一下当浅色**
（参见第四节：底和字必须整套重配）。
