# 别让它跟上一个长一样，也别为一句抱怨重做

**这两件事表面不相干，其实是同一个病：模型没有记忆，也没有"到此为止"的手感。**

- 「这次跟上次不一样」——一条从来没有生效过的规则。你没有跨会话记忆，所谓的"记住了"全在同一轮上下文里，
  新一轮打开它等于没写。这条规则在实际生成里常常落空：**它是唯一一条从未真正生效过的规则。**
- 「我说一句你就重做」——也是同理：没有"改到哪一层为止"的判断，只能从头再来一遍。

所以这两件事都要**落到文件和表格上**，不能靠意志。

---

## 一、先划个范围：什么时候不该用这一节

- **同一个项目的 iteration 不算。** 给用户自己的工作台改版、加模块、换皮肤，轴对不上也要保持连贯——
  他的东西就该像他的东西。这一节管的是**给不同需求/不同人搭新台子**。
- **导航栏、抽屉、 TabBar 这类"家具"不参与旋转。** 每个 App 的底部栏就该长得像别人的底部栏，
  为了不一样而弄得不一样，是拿可用性换新鲜感。

---

## 二、五轴坐标（给工作台用的一版）

同类生成器用五个**互相正交**的轴组合出"灵魂"。为什么必须是组合而不是一张十行的清单：
**模型从十个选项里挑，每次都会命中同样那两三个（它被见得最多的东西拉走）。** 五轴各取一个值，是几千种组合。

| 轴 | 含义 | 工作台场景里常见的值 |
|---|---|---|
| **A 配色结构** | 色是怎么分布的 | 单色系一主色 / 双色互补 / 暖多色带 / 冷底 + 一个热点色 / 低饱和莫兰迪 / 近乎单色靠明度分层 |
| **B 字体关系** | 字之间怎么分出层级 | 无衬线粗细阶梯 / 衬线标题 + 无衬线正文 / 等宽数据 + 无衬线叙述 / 单一无衬线靠字距字重分层 |
| **C 主布局族** | 整屏骨架 | 左侧栏 + 网格 / 顶部结论带 + 卡片流 / 双栏（列表 + 详情）/ 看板表格 + 侧面板 / 时间轴 / 全屏 Hero + 分区滚 |
| **D 首屏形态** | 打开第一眼是什么 | 结论条 + 今天的三件事 / 大数字带 / 今日清单 / 卡片故事流 / 待处理告警列表 / 曲线 + 一句话 |
| **E 材质隐喻** | 触感 | 深蓝分层面板 / 纸感暖色 / 磨砂玻璃 / 终端荧光 / 扁平纯色块 / 卡片带阴影浮起 |

**规则：一个新的台子必须跟用过清单里最近那几条至少有 3/5 个轴不同。**
另外三条我们从别人那里照抄的纪律：

- **开工前先读用过清单**，不是交付后补记。
- **两个方向同样说得通时，用随机数破，不要用意志破。** 模型在平局里会默默选它见过最多的那一个，
  而它自己完全意识不到。想推翻随机结果可以，但要在注释里写下理由。
- **饱和的搭配当默认值就是偷懒**：一律"深蓝 + 紫色发光"、"米色 + 铜色"这种组合，看见了要主动换掉一个轴。

## 三、用过清单（这是让它生效唯一的东西）

文件放在项目里，跟着 skill 走不合适——它是**每个工作目录自己的历史**：

```
<work>/工具/页面自测/build-log.json
```

结构：

```json
{
  "builds": [
    {
      "date": "2026-10-31",
      "name": "示例·某人创作台",
      "structure": "feed + monitor + ledger",
      "dials": { "A": "冷底 + 一个热点色", "B": "无衬线粗细阶梯",
                 "C": "左侧栏 + 网格", "D": "顶部结论带 + 卡片流",
                 "E": "深蓝分层面板" },
      "kept": ["判断不改的东西写在这里，下次别动它"],
      "note": "这次哪些判断后来被用户否掉了"
    }
  ]
}
```

三条使用约束：

1. **开工必读，写进去才有下一次。** 交付完当天就写，别指望以后记得。
2. **`kept` 字段比 `dials` 更值钱**——它记的是"哪些东西改了会挨骂"。
3. 条目留最近 20 条就够，删掉更早的。

## 四、交付后的迭代映射表（单个抱怨不许重做）

**用户说一句抱怨，你要能指出它在哪一层，然后只动那一层。**
整个页面重做一次，等于把上次他认可的东西一起丢掉，他下次就不敢提意见了。

| 他说 | 大概率不是 | 改这一层 | 不许做 |
|---|---|---|---|
| 「太素了 / 不好看」 | 不是要加数据、加模块 | 视觉层：层次（三层底）、质感底线、皮肤色 | 不动口径，不动结构 |
| 「太花了 / 看着累」 | 不是信息太多到必须删模块 | 降动效幅度、收强调色数量、加留白 | 不推倒布局重排 |
| 「换个颜色 / 换套皮肤」 | 不是要重做界面 | 只换皮肤那组 token（`--dxac` 那一层） | 不整份 CSS 重写，不动结构 |
| 「数据看着不对」 | 不是显示问题 | 查口径单一来源（铁律 3）和数据块 | 不改 UI，不"换算一下好看点" |
| 「不知道数据是不是新的」 | 不是让用户自己去看时间戳 | stale 没渲染（铁律 6）：补告警条 + 脚本 alerts | 不重抓、不改颜色糊过去 |
| 「每天打开都一样 / 没啥可看的」 | 不是模块不够 | 首屏没有变量（定义层 3.1）→ 补字段或换钩子 | 不靠加三个模块救它 |
| 「手机上点不准 / 按了没反应」 | 不是电脑布局要改 | 移动端六条 M1–M6 + 触控目标 44px + `:active` 反馈 | 不为迁就手机重排整屏 |
| 「太慢 / 卡」 | 不一定是动画 | 先看是不是一次性渲染了几千条 / 数据块太大 | 不先降视觉当替罪羊 |
| 「想加个 X 功能」 | 不等于现在就加 | 走规模闸门：先进分期还是本期 | 一次加三个模块 |
| 「我要那种官网的感觉」 | 不是一样的效果换给我 | 先找源文件（视觉体系第七节：搜全盘找 `app.css`），再谈复刻 | 不凭截图猜，不一句"做不到"打发 |
| 「我觉得不安全 / 不敢用自己的真数据」 | — | 这是红线不是迭代：先看数据有没有被写进公开发布的包 | 不许说服他放宽，只许当场修 |

> 一句话收口：**挑错的对象要具体，修改的范围要最小。**
> 用户指出的是一个层次，不是一个页面。
