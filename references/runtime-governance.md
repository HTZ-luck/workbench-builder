# 运行期治理：口径、历史与告警

> **适用边界**：台子跑起来之后，每天抓取 / 构建 / 发布 / 迭代这一段。
> 与铁律 1-7（数据真实性）、`data-contract.md`、G1-G8、A1-A12 **叠加执行，不替换任何一条**。
> 全部编号用 B1-B11，不占用主文件 23 条铁律、也不占用 G / A 编号。
> 每一条的落地位置都指向本仓库内可核对的文件或本机实测结论。

## 一、为什么补这一段

前面几节管的是「页面对不对」「交付是不是当初那一版」。还有一类失败只在**长期运行**里出现：
同一份口径散在四个地方、其中一处悄悄旧了；昨天写下的结论被今天的抓取盖掉；
样本只有两三条却摆出一个看起来很确定的百分比；构建脚本读文件失败，页面安安静静什么都不显示。

本机目录级静态重建实测：21 个相关文件、约 3.5 MB 文本、32,571 个 AST 节点、
22,134 个语义节点、51 条 findings，**但只解析出 2 个独立 JS 文件**，其余是 HTML / CSS / Python。
静态工具自己在限制里写明：HTML 与脚本按惰性文本解析、启动代码从未执行、
「静态关系不证明运行时执行」。所以「几处清单是否一致」「历史有没有被回改」
「告警有没有真的上墙」，静态扫描一律查不出来，必须在构建脚本和页面上做成显式断言。

还有一次更极端的本机实测：对一个单文件全内联页面做同样的目录级静态重建，
相关文件 1 个、解析出的独立 JS **0 个**、遍历到的 AST 节点 **0**、语义图只有 1 个节点，
工具在限制里直接写明「内联脚本体未被分析；端点、存储、导入等事实在证据中缺失」。
也就是说，页面里全部的业务逻辑、账号分区、时间戳写入、估算公式，静态重建一项都看不见。
**工具跑出报告不等于代码被检过**，单文件架构下只信 jsdom 回归与浏览器注入探针（A2）。
下面 B7-B11 这几条，正是这类「静态查不出、天天在用」的失败。

## 二、补进来的 11 条

**B1 同一口径只认一个真源；多处不一致要报出来，不能静默挑一个用。**

- 算法、公式、权重、源清单、页面清单、阈值，只要出现在两处以上，就指定一个文件为**唯一真源**；
  其余位置写「以 X 为准」的引用，不要各自复制一份值。
- 构建时逐处比对。不一致不许静默选一个继续跑：把冲突项收集进 alerts，
  页面上写明「口径冲突：A 处是 X，B 处是 Y，本次以 X 为准」。
  文档里那份过时描述不要由构建脚本去「顺手改正」——只读只报，绝不改写正本。
- **把同步清单升级成机器断言**。`data-contract.md` 第六节已经列了「加一个源要同步 6 处」，
  导航数量也收敛到了 `NAV_EXPECT` 一处，但清单本身还是靠人记。
  构建脚本的页面清单、发布脚本的页面清单、回归里的期望清单，三方必须在自检里断言相等；
  字段清单、注入映射、总控环节清单同理，能断言的都别留在文档里。
- 这类坑的真实代价：发布清单长期少列两页，那两页一直在生成却从没被发出去；
  改定时或加源要同步四处，漏一处页面就显示旧说明。两处都是「跑成功了但东西不对」，
  四道关和对比度探针都查不出来。

落地：`references/data-contract.md` 第六节、`scripts/` 的发布前自检、A2 的探测器确认真跑过。

**B2 写下的判定是历史，不是可覆盖的缓存。**

- 已写下的判定、已发布的快照、用户录入的结论，事后不许回去改。
  要修正就**追加一条新记录**或新建一个版本文件，原文原值保留；复盘写进独立段。
- 纯格式修正算例外，但要走显式开关并留痕，让提交记录里看得见有人破过例。
  否则「改一下措辞」会慢慢变成「把不利的旧结论改掉」。
- 抓取历史按日期另存，不覆盖昨天那份。
  `data-contract.md` 第四节的「0 条不覆盖」管的是**别用坏数据盖好数据**，
  这条管的是**别用新结论盖旧结论**，两件事。
- 与 G8「新模块用新 key 不改老键」是同一条纪律的两面：G8 管兼容，这条管留痕。

落地：`STORE` 封装、导出 JSON 里的历史段、`scripts/README.md` 的种子数据 bug 记录。

**B3 真实但不足以支撑结论的数，也要标出来。**

- 样本不足时，评分、排序、占比不许装作可信：页面上明写当前样本数和「样本不足，低置信，先收样本」。
  未校准的公式与权重一律标「占位」，不许拿它决定发不发、做不做。
- **每个阈值要有出处标签**：来源建议 / 系统默认 / 本人数据结果。改阈值时连标签一起改。
  这一条直接压住「随手写个 ≥3 倍就算爆款，过两周谁也说不清 3 是哪来的」。
- **反例必须保留**：结构过关但结果差、结构不完整但结果好的条目，不许为了维护公式把它删掉。
- 示例数据在 G4 的 `demo:true` 和一键清空之外，页面上还要标「示例，非真实」；
  示例数字别挑漂亮的大数，那会让人误以为是实绩。
- 与铁律 1-7 是同一件事的两半：那边禁编造，这边管「数字是真的，但撑不起这个结论」。

落地：主文件第七节红线、`workbench-definition.md` 第三节、A8 的假精确数字清单。

**B4 人工区与机器区分区写入，机器只替换自己那一段。**

- 同一个文件里，人工挑出来的内容和脚本抓来的内容分区存。
  抓取脚本只替换自己那一段，保留文件头和人工区；反过来加工时也不用管机器段的格式。
  谁先谁后都安全，这是分区的全部意义。
- `data-contract.md` 第四节已有「全源失败不写盘」。这里补两条：
  **部分源不可达**要把源名和真实失败原因写进页面，不用占位内容补足；
  **空结果给「待加工」占位**，不自动编造一份精选。
- 回归断言**验规则本身，不绑会轮换的真实值**：断言「人工挑的条目在抓取后仍在」
  「空文件产出的是待加工占位而不是编造内容」「有源不可达时页面含该源名」。
  与 `ht_regress.js` 的口径一致。

落地：`data-contract.md` 第三、四节、A2、页面自测脚本。

**B5 构建期的异常要变成看得见的告警清单。**

- 缺文件、解码失败、坏 JSON、缺目录、解析不到条目，全部收集成 `warnings` 清单，
  随数据块注入并在页面上可见。**不许静默吞错**，也不许因为一条坏数据整站崩；
  能降级的降级，但必须留一条 warning。
- `warnings` 与业务数据走同一块，JSON 注入时 `</` 转义 `<\/`（`data-contract.md` 第二节已有）。
- 构建脚本只读用户正本，不回写、不修正、不「顺手帮他把格式整理一下」。
- **本地服务默认只监听 127.0.0.1**。要放到公网，先在页面或说明里提醒
  「页面内嵌了全部数据，需自行加访问控制」。这与红线「不把个人数据焊死在代码里挂公网」
  是一体两面：那边管交付包，这边管运行中的服务。
- 发布时清掉上一版残留资源，并在回归里断言过期产物不在发布目录里。

落地：`data-contract.md` 第二、三节、A2、发布脚本、发布前自检。

**B6 状态文件带版本号，开场先给一份状态报告。**

- 状态 / 配置文件带显式 `schema_version`。版本不一致给**非阻塞提示**，
  既不阻断使用，也不静默按新格式去读老数据；同时提示怎么迁移。
- 开场状态报告 4-6 行，从状态文件算，不靠回忆：存量、待处理、
  上次成功刷新距今天数、样本置信度、待办告警；末尾明确「先不改任何东西，等用户决定」。
  这是把「闸门不替用户拍板」做成看得见的一条，而不是一句纪律。
- 与 G8 叠加：G8 管向后兼容，这条管版本可见、开场有数。

落地：`STORE` 封装、`build-guardrails.md` G8、主文件第二节访谈闸门。

**B7 每个数字都要标数据性质，估算必须把假设写出来。**

- 页面上的数分三类：**实测**（抓到或本人录入）、**估算**（用假设参数推算）、**占位**（未校准 / 待补）。
  每个指标旁逐条标注，不只给首屏那几张静态卡片加；脚本动态渲染出来的指标一样要带标签。
  这和铁律 11 的来源徽章是两件事：徽章答「哪来的」，这三条答「这个数是不是算出来的」。
- **估算必须同时写出假设**：「按点击率 15% 反推曝光」而不是只写一个曝光数。
  用倍数、系数、均值补出来的留存、漏斗、预测值，全部归估算，不许因为格式整齐就混进实测。
- 同一个模块里实测与估算混排时，**整体按最弱口径标注**，别让读者以为一屏数字全是真的。
- **图例声明的档位必须在数据里真出现**。本机清点单文件页面时见过：图例声明了两档，
  实际注入的标签全部落在实测一档，而脚本里另有若干假设公式在算数——
  标注挂了却没人用，比不标更误导。回归里要断言「声明的每一类标签都至少出现一次」，
  以及「存在估算公式时，页面上能检索到对应的假设说明」。
- 缺数据直接写「数据不足」并给原因，不许填 0、不许留空白、不许拿相邻指标凑一个近似值。
  0 是真实值，「没有采到」不是 0。

落地：B3 的低置信标注、铁律 11 的来源徽章与证据行、`data-contract.md` 第二节字段表、A2 的页面断言。

**B8 时间只有一个真源；点了刷新不等于数据更新了。**

- 至少分清两个字段：`fetchedAt`（**数据截至**，快照里那批数对应的时间）和
  `lastRefreshRequest`（**上次发起刷新**）。统计窗口再单独一个字段。三者不许互相代替。
- 侧栏、模块副标题、等级说明、报告落款、导出文件头，**全部从同一个字段渲染**。
  不许在 HTML 里写死一个日期，也不许一句文案里手抄一遍窗口。
  本机清点见过同一份数据里散着多处硬编码日期，侧栏、等级说明、报告落款各写一个不同口径，
  谁也说不清到底哪天的数据。
- **只有新快照真正落盘并通过校验，才更新 `fetchedAt`**。
  点了按钮、发了请求、弹了「请稍候」、甚至脚本跑完但没拿到数，都不算更新。
  请求发出后还没落盘，页面保持旧时间戳并显示「等待更新」状态；
  失败就沿用旧值并按 `stale` 三件套写真实原因（`data-contract.md` 第三节）。
- 页面要能直接读出「数据截至 X，距今 N 天」，别只显示一个孤零零的时间。
  这条压住的是「把计划写成已完成」：刷新请求写进时间戳，第二天看起来就像数据刚更新过。
- 与 B1 是同一族但管的东西不同：B1 管口径清单同步，B8 管时间语义与假完成。

落地：`data-contract.md` 第二、三节 `fetchedAt` / `stale` 三件套、B1 唯一真源、A2 页面断言。

**B9 一个台子管多个主体时，按主体分区存；切换主体要全站重渲染。**

- 多账号、多项目、多平台、多店铺，每个主体的数据**独立分区存**，
  主体清单与「当前主体索引」分开存，别把身份和数据焊在同一个对象里。
- 切换主体时，KPI、列表、图表、判定、报告正文、导出文件名**全部从当前主体数据重渲染**，
  顶部身份一起换。只改名字和头像、数字还留着上一个主体的，是最危险的一种串数据。
- **没有数据的主体给空态**：写明「这个主体还没有数据，怎么采」，
  不许沿用旧主体的数字，也不许复制一份旧数据过去充数。
- 主体身份别硬编码在标题或标签里；新增主体走独立录入，字段从零开始。
  导出 / 导入按主体分别存，恢复时先问恢复哪一个。
- 回归断言验「切到空主体后页面不含上一主体的任何数字」「切回来数据完整」，
  不绑具体数值。这与 B4 的分区写入是同一条纪律：那边分人工区 / 机器区，这边分主体。

落地：`STORE` 封装、G1 的 `refreshAll()` 单向调度、G8 新 key 不改老键、A2 回归断言。

**B10 判定行写满三件套，结论强度不许超过依据强度。**

- 每条下结论的行，都要能核到 **依据来源 + 统计窗口 + 原始数值**：
  「后台数据（起止窗口）：投稿 0、播放 3、主页访问 10」，
  而不是「近期表现不佳」这种没法核对的话。铁律 11 要求来源徽章与可点证据行，
  这里补的是证据行里到底要写什么。
- 依据只有两三条、窗口只有几天，就别下「长期趋势」「整体风险」这类大结论；
  写成「样本不足，待验证」，并按 B3 标低置信。**结论的强度由依据撑，不由语气撑**。
- 没有依据的判断不许伪装成结论：标「推断」，另起一段写清是推断、推断自哪几条、
  需要补什么数据才能确认。反例与不利数据要留在依据里，不许只挑支持结论的那几条。
- 判定行与它引用的数据必须同窗口。用上月数据算出的等级，旁边写着本周窗口，就是错的。

落地：铁律 11、B3 低置信与反例保留、B7 数据性质、`workbench-definition.md` 第三节。

**B11 两档阅读密度与打印导出，都要真能用。**

- 同一份数据给两档：速览只留结论和关键数，完整版展开依据、明细、明细下的解释。
  切换要**真的隐藏元素**（CSS 里得有对应规则），按钮文案、状态、可访问名称跟着变，
  切回完整版内容一条不少。只加个 class 而样式里没定义，等于按钮是摆设。
- 提供「导出 / 打印」按钮就必须写 `@media print`：隐藏侧栏与导航、去掉固定定位和悬浮层、
  浅底深字、展开所有折叠块、默认按完整版输出、页脚带数据截至时间（B8）。
  本机清点见过只有打印调用、没有打印样式的页面——深色底加固定侧栏全打出来，
  纸面上根本没法看。这与铁律 9「长得像链接就必须真能点」是同一条纪律。
- 打印与速览状态不许影响数据本身：切档只改显示，不重写数据、不改时间戳。
- 回归断言验「速览态下依据行不可见、完整版可见」「打印样式里侧栏为隐藏」
  「切档前后数据块字节一致」。

落地：铁律 9、A1 承诺回对、A2 探测器确认真跑过、`visual-qa.md` 的打印展开、`data-contract.md` 第二节。

## 三、一轮运行里怎么用

1. **抓**：B4 分区写入；B9 按主体分区；部分源失败如实记录；全源失败不写盘（`data-contract.md` 第四节）
2. **构建**：B1 三方清单断言 + 口径冲突进 alerts；B5 warnings 注入；B2 快照按日另存；
   B8 只有落盘校验通过才写 `fetchedAt`
3. **页面**：B3 置信度 / 阈值出处 / 示例标注；B7 数据性质与估算假设；B10 判定行三件套；
   B5 告警可见；B6 开场状态报告；B9 切换主体全站重渲染；B11 速览与打印真能用
4. **发布**：B5 清过期产物 + 访问控制提醒；B8 各位置时间同源；
   回归断言验规则本身不绑真实值，并断言 B7 / B9 / B11 的三组状态

## 四、明确的取舍

| 不做 | 为什么 |
|---|---|
| 某个内容行业的评分维度、选题闸门、文稿节奏标尺 | 那是领域方法论，不是通用工作台规则；铁律 21 要求按数据结构配模块，不按行业抄清单 |
| 某个平台的权重算法、完播率诊断口径、风险条款清单 | 同上，且平台规则会变；只取「判定行要带依据」的形式，不取判定内容 |
| 依赖特定笔记软件的双向链接、查询插件、模板引擎 | 会拆掉单文件零外链地基，也把「换台电脑还能打开」变成空话 |
| 在线字体、图表 CDN、动画库 | 撞铁律 1 零外链单文件；图表用手写 SVG（A9），字体用系统栈（A12） |
| 登录 / 验证码 / 扫码流程与凭证管理 | 属本机服务的接入细节，不是工作台页面规则；只在 B5 提访问控制边界 |
| 写死的深色主题与某个行业的配色 | 与 `visual-system.md` 的主题 / 皮肤体系冲突，换肤要底和字一起换 |
| 「预计提升 25-35%」这类没有实测出处的效果数字 | 撞红线「禁编造数字」，也撞 B7 的估算必须写假设 |
| 把定时任务写死成某一种操作系统的守护方式 | 定时是本机能力，工作台要能在不同机器上跑；只写清「要定时 + 失败退出码」，不锁实现 |
| 盲测隔离、按偏差次数迭代评分标准这类校准流程 | 属于人在回路的判断力训练；工作台不替人下结论，闸门本来就该用户拍板 |
