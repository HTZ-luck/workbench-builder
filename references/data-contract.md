# 数据契约速查（页面数据块 ↔ 抓取脚本）

这一份是**速查**，不是新规则。所有条目的权威解释在 SKILL.md 的铁律里（每条都标了出处），
这里只把「页面读的那份格式」和「脚本写的那份格式」摊在一页上，免得改的时候满文件找。

> 为什么单列一份：数据契约散在铁律 2 / 5 / 6 和注入脚本里，加一个源要翻四五个地方。
> 而这是最容易出错的一层——**格式错一点不会报错，只会让页面安静地显示错数据**。

> **关于命名**：`data-contract` 是通用叫法。本文件是一份速查，
> 所有条目的权威解释见 SKILL.md 的铁律；字段数量、抓取环节按自己项目的 config 为准。

## 一、页面侧：数据块长什么样

```html
<script id="intelData" type="application/json">
{"fetchedAt":"2026-11-01","stale":false,"items":[...]}
</script>
```

| 约定 | 说明 | 出处 |
|---|---|---|
| 位置 | **`</head>` 之前**，且在主体 `<script>` 之外 | 铁律 2 |
| 一个源一个块 | id 用 `xxxData`，渲染函数只认 id | 铁律 2 |
| `</` 必须转义 | 条目文本里出现 `</script>` 会提前结束标签，整块变语法错误 | scripts/README 细节 2 |
| JSON 必须合法 | 自检会查；不合法会让整页 JS 挂掉 | 铁律 15 第 2 关 |

**为什么必须在 `</head>` 前**：init 是立即执行的 IIFE，数据块放到 body 末尾时它已经跑完了，
首屏三张卡全空——页面看起来正常，只是没数据。这是真实踩过的（铁律 2）。

## 二、字段级约定

| 字段 | 谁写 | 约定 |
|---|---|---|
| `fetchedAt` | 脚本 | 抓取日期，字符串。**相对时间（「3 小时前」）必须换算成真日期**再写进去，认不出就丢弃 |
| `stale` / `staleSince` / `staleReason` | 脚本（失败时） | 三件套，见下节 |
| 数值字段 | 脚本 | **抓不到就留空或写「平台未提供」，绝不补 0**——0 是真实的数，会把均值分母搞错（铁律 4） |

## 三、stale 三件套（失败时才有）

| 字段 | 内容 |
|---|---|
| `stale` | `true` |
| `staleSince` | 从什么时候开始是旧的 |
| `staleReason` | **真实的错误输出并分类**：登录态过期 / 没返回数据 / 调用异常。**不许写死一句「没抓到」** |

配套的四条（缺一条等于没写，铁律 6）：
1. 每个消费该数据的视图都要渲染告警条，写清「旧到什么时候 + 为什么 + 具体修法命令」
2. 混排视图也要一句轻提示
3. **不 stale 时必须不渲染**——天天挂告警等于没告警
4. 总控脚本把「stale 且超 24 小时」拎进 alerts，**汇报第一句必须是它**

## 四、写入侧：脚本的契约

| 约定 | 说明 |
|---|---|
| **0 条不覆盖** | 抓到 0 条时不写盘、不写空块，沿用上一次成功的数据（铁律 5） |
| 失败沿用 + 打 stale | 宁可显示旧的并标明，不许显示空的或假的 |
| 剥 emoji | 源数据里的 emoji 会污染页面（零 emoji 是硬要求） |
| 弹掉代理变量 | 运行环境注入的代理变量常返 502，会伪装成「对方接口挂了」 |
| 登录态失效 | 必须 `return 2`（return 0 = 定时报成功却一条没有） |

## 五、退出码契约（总控脚本）

| 码 | 含义 | 发布怎么办 |
|---|---|---|
| 0 | 正常 | 照常发布 |
| **2** | **有警告但数据还在** | 照常发布，**但汇报第一句必须是 alerts** |
| 1 | 真失败 | 不发布，保留线上旧的 |

> 「2」当年设计成「照常发布」，结果每次都被判「成功」，数据断了 38 小时没人发现（铁律 6）。

## 六、改一个源时要同步的地方

这是「改一处要同步 N 处」的重灾区。加/减一个源至少过一遍：

1. 页面里的数据块（`<script id="xxxData">`）
2. 渲染函数里读这个块的地方
3. 注入脚本的映射（`inject_data.py` 的块名清单）
4. 总控脚本的 `STEPS` / 分班（`BATCHES`）
5. 消费它的视图有没有 stale 告警条（铁律 6）——**最容易漏的就是这条**
6. 自检里的数据块齐全性检查

导航数量同理，但那个已经收敛到 `wbconfig.py` 的 `NAV_EXPECT` 一处（见 scripts/README）。
